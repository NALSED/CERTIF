## StatefulSet

---

- Cette fonctionnalité gère les besoins `stateful` des Pods. Le `stateless` est géré par `Deployment`.

=== Skills StatefulSet ===

- `PVC propres` : chaque Pod reçoit son propre volume, créé automatiquement depuis le modèle `volumeClaimTemplates`.

- `Noms fixes` : le nom (`web-0`) et le volume attribué ne changent pas au redémarrage.

- `DNS` : via un Service headless (`clusterIP: None`) et `serviceName`, le nom fixe suit l'IP à chaque redémarrage. On joint ainsi un Pod précis par son hostname (`web-0.mon-service`).

- `Ordre par ID` : les Pods démarrent de 0 à N, un par un, et s'arrêtent dans l'ordre inverse. Le nœud principal est ainsi prêt avant les réplicas.

---

**=== Exemple ===**

- Ici l'exemple portera sur un fichier .yaml trouvé sur [https://kubernetes.io/fr/docs/concepts/workloads/controllers/statefulset/](https://kubernetes.io/fr/docs/concepts/workloads/controllers/statefulset/)

- Pour definir un état Stateful dans Kubernetes des lignes sont obligatoires pour géner un êtat `Statefull` :

**[ANCRE #1]** `clusterIP` : None` => Rend le service `Headless`
   
**[ANCRE #2]** `serviceName` : "NAME" => Nom exact du Headless Service
 
**[ANCRE #3]** `name` : NAME => Doit correspondre au name sous volumeClaimTemplates
 
**[ANCRE #4]** `volumeClaimTemplates` : => Génère un PVC par Pod (www-web-0, www-web-1...)
 
**[ANCRE #5]**  `storageClassName` : "standard"


````
apiVersion: v1
kind: Service
metadata:
  name: nginx
  labels:
    app: nginx
spec:
  ports:
  - port: 80
    name: web
  clusterIP: None <========= [ANCRE #1]
  selector:
    app: nginx
---
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: web
spec:
  selector:
    matchLabels:
      app: nginx # doit correspondre à .spec.template.metadata.labels
  serviceName: "nginx" <========== [ANCRE #2]
  replicas: 3 # est 1 par défaut
  template:
    metadata:
      labels:
        app: nginx # doit correspondre à .spec.selector.matchLabels
    spec:
      terminationGracePeriodSeconds: 10
      containers:
      - name: nginx
        image: registry.k8s.io/nginx-slim:0.8
        ports:
        - containerPort: 80
          name: web
        volumeMounts:
        - name: www <============== [ANCRE #3]
          mountPath: /usr/share/nginx/html
  volumeClaimTemplates: <=========== [ANCRE #4]
  - metadata:
      name: www
    spec:
      accessModes: [ "ReadWriteOnce" ]
      storageClassName: "my-storage-class" <============== [ANCRE #5]
      resources:
        requests:
          storage: 1Gi
````

````
# ==============================================================================
# PARTIE 1 : HEADLESS SERVICE (Identité Réseau & Résolution DNS)
# ==============================================================================
apiVersion: v1
kind: Service
metadata:
  name: nginx                 # Nom du service (utilisé pour construire le domaine DNS)
  labels:
    app: nginx
spec:
  ports:
  - port: 80
    name: web
  clusterIP: None             # [ANCRE #1] Désactive l'IP virtuelle (ClusterIP) -> Mode "Headless"
                              # Permet à CoreDNS de pointer directement sur les IPs individuelles des Pods
  selector:
    app: nginx                # Sélectionne les Pods portant le label "app: nginx"

---
# ==============================================================================
# PARTIE 2 : STATEFULSET CONTROLLER (Gestion de l'État & Ordre des Pods)
# ==============================================================================
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: web                   # Nom du StatefulSet (génèrera les pods web-0, web-1, web-2)
spec:
  # --- Alignement des Sélecteurs ---
  selector:
    matchLabels:
      app: nginx              # Doit correspondre EXACTEMENT aux labels du spec.template.metadata.labels

  # --- Liaison Réseau ---
  serviceName: "nginx"        # [ANCRE #2] Lien direct vers le Headless Service (metadata.name: nginx)
                              # Génère les FQDN : web-0.nginx.<namespace>.svc.cluster.local

  # --- Dégaine de réplication ---
  replicas: 3                 # Déploie 3 pods de manière séquentielle (web-0 -> web-1 -> web-2)

  # ============================================================================
  # PARTIE 3 : TEMPLATE DU POD (Définition des Conteneurs)
  # ============================================================================
  template:
    metadata:
      labels:
        app: nginx            # Label appliqué à chaque Pod créé (aligné avec selector.matchLabels)
    spec:
      terminationGracePeriodSeconds: 10
      containers:
      - name: nginx
        image: registry.k8s.io/nginx-slim:0.8
        ports:
        - containerPort: 80
          name: web

        # --- Montage du Volume dans le Conteneur ---
        volumeMounts:
        - name: www           # [ANCRE #3] Doit correspondre EXACTEMENT au name sous volumeClaimTemplates
          mountPath: /usr/share/nginx/html  # Chemin dans le conteneur où le volume est monté

  # ============================================================================
  # PARTIE 4 : STOCKAGE PERSISTANT (Création Dynamique des PVC)
  # ============================================================================
  volumeClaimTemplates:       # [ANCRE #4] Génère automatiquement un PVC dédié par Pod (www-web-0, www-web-1...)
  - metadata:
      name: www               # Nom du template de volume (lié à volumeMounts.name)
    spec:
      accessModes: [ "ReadWriteOnce" ]
      storageClassName: "my-storage-class"  # [ANCRE #5] Nom de la StorageClass demandée à l'examen
      resources:
        requests:
          storage: 1Gi        # Espace disque réservé pour CHAQUE Pod
````
