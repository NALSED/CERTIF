# Kustomize

---

- Kustomize permet d'appliquer des modification sur un déploiment par environement.

**=== Exemple ===**

- Environement :
   - dev
   - staging
   - prod

- On souhaite que le déploiement des application via Helm soit différente en terme de CPU, replicas, ou alors donner un préfixe, namespace ou label.

- (Pour plus d'information sur les possibilités [https://kubernetes.io/docs/tasks/manage-kubernetes-objects/kustomization/](https://kubernetes.io/docs/tasks/manage-kubernetes-objects/kustomization/))

### **=== Marche à suivre ===**

`[NOTE]`

- les dossiers `base` et `overlay` sont des conventions, cela fait partie des bonnes pratiques afin de se retouver dans une configuration avec des environement multiple.

## `-1-` Créer la base

`- 1.1` Créer le dossier
````
mkdir -p kustomize/base
````

`- 1.2` Créer le fichier de Base pour l'application (Ici nginx)
````
vim kustomize/base/deployment.yaml
````
````
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 1
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: web
        image: nginx:1.25
````

`- 1.3` Créer le service de base 
````
vim kustomize/base/service.yaml
````
````
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
````

- `1.4` Créer le fichier kustomization.yaml pour la base
````
vim kustomize/base/kustomization.yaml
````
````
resources:
  - deployment.yaml
  - service.yaml
````

**VERIFICATION**
````
kubectl kustomize kustomize/base
````

**DEPLOIEMENT**
````
kubectl apply -k kustomize/base
````

**A ce stade** Voici l'arborécence du projet de base.
````
kustomize/
└── base/
    ├── deployment.yaml      # replicas: 1, image par défaut
    ├── service.yaml
    └── kustomization.yaml
````

## `-2-` Création d'overlay

`[NOTE]`


- Création d'overlay (modification du projet base) un par environement (dev, staging, prod, etc...).

- Il existe `2` maniéres de créer un `overlay` en fonction de ce que l'on veux modifier dans **base**.

### `- 2.1` Utiliser le fichier `kustomize.yaml` présent dans chaque environnenement que l'on souhaite modifier.

**=== Quand utiliser ce cas de figure ===**

- Losque que l'on veux manipuler un champs intégré à `kustomize`, (si le binaire kustomize, est installé => kustomize edit set <TAB>) :
   - annotation
   - buildmetadata
   - configmap
   - image
   - label
   - nameprefix
   - namespace
   - namesuffix
   - replicas
   - secret         
````
kustomize/
└── mon-projet1/
   ├── base/
   │   ├── deployment.yaml
   │   ├── service.yaml
   │   └── kustomization.yaml
   └── overlays/
       ├── dev/
       │   └── kustomization.yaml <---------
       └── prod/                            |----- Utiliser directement ces fichiers
           └── kustomization.yaml <---------
````

**=== EXEMPLE ===**
````
vim /kustomize/mon-projet1/overlay/dev/kustomize.yaml
````
````
resources:
  - ../../base
namespace: prod
namePrefix: prod-
replicas:
  - name: web
    count: 5
images:
  - name: nginx
    newTag: "1.27"
labels:
  - pairs:
      env: prod
````

---

### `- 2.2` Utiliser un fichier **patch**, et le déclare dans le fichier `kustomize.yaml`, et l'intégrer à l'environement corespondant.

**=== Quand utiliser ce cas de figure ===**

- Losque les `champs` que l'on souhaite modifier, **ne font pas partie** des champs intégré a `kustomize`
````
kustomize/
└──  mon-projet1/
   ├── base/
   │   ├── deployment.yaml
   │   ├── service.yaml
   │   └── kustomization.yaml
   └── overlays/
       ├── dev/
       │   └── kustomization.yaml
       └── prod/
           ├── kustomization.yaml   <----  Utiliser ces deux fichiers
           └── patch-replicas.yaml  <----  Utiliser ces deux fichiers

````

**=== EXEMPLE ===**

`-1-` Kustomize.yaml
`-2` Fichier de patch

`=== kustomize ===`
````
vim /kustomize/mon-projet1/overlay/prod/kustomize.yaml
````
````
resources:
../../base

patches:
  - path patch-prod.yaml
    target:
      kind: Deployment
      name: web
````


`=== Fichier Patch ===`
````
kustomize/mon-projet1/overlays/prod/patch-prod.yaml
````
````
- op: add
  path: /spec/template/spec/containers/0/resources
  value:
    limits:
      cpu: 500m
      memory: 256Mi
````

---

### `- 2.3` Vérrif du fichier
````
kubectl kustomize kustomize/overlays/prod/
````

### `- 2.4` Déploiement
````
kubectl apply -k overlays/prod/
````
