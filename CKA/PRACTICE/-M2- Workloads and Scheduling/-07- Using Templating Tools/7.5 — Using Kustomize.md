## Kustomize

---

- Kustomize permet d'appliquer des modification sur un déploiment par environement.

**=== Exemple ===**

- Environement :
   - dev
   - staging
   - prod

- On souhaite que le déploiement des application via Helm soit différente en terme de CPU, replicas, ou alors donner un préfixe, namespace ou label.

- (Pour plus d'information sur les possibilités [https://kubernetes.io/docs/tasks/manage-kubernetes-objects/kustomization/](https://kubernetes.io/docs/tasks/manage-kubernetes-objects/kustomization/))

## **=== Marche à suivre ===**

`[NOTE]`

- les dossiers `base` et `overlay` sont des conventions, cela fait partie des bonnes pratiques afin de se retouver dans une configuration avec des environement multiple.

### `-1-` Créer la base

`- 1.1` Créer le dossier
````
mkdir -p kustomize/base
````

`- 1.2` Créer le fichier de Base pour l'application (Ici nginx)
````
vim kustomize/base/deployment.yaml
````
````
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 1
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: web
        image: nginx:1.25
````

`- 1.3` Créer le service de base 
````
vim kustomize/base/service.yaml
````
````
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
````

- `1.4` Créer le fichier kustomization.yaml pour la base
````
vim kustomize/base/kustomization.yaml
````
````
resources:
  - deployment.yaml
  - service.yaml
````

**VERIFICATION**
````
kubectl kustomize kustomize/base
````

**DEPLOIEMENT**
````
kubectl apply -k kustomize/base
````

**A ce stade** Voici l'arborécence du projet de base.
````
kustomize/
└── base/
    ├── deployment.yaml      # replicas: 1, image par défaut
    ├── service.yaml
    └── kustomization.yaml
````

### `-2-` Création d'overlay

`[NOTE]`


- Création d'overlay (modification du projet base) un par environement (dev, staging, prod, etc...).

- Il existe `2` maniéres de créer un `overlay` en fonction de ce que l'on veux modifier dans **base**.

`-1-` Utiliser le fichier `kustomize.yaml` présent dans chaque environnenement que l'on souhaite modifier.

**=== Quand utiliser ce cas de figure ===**

- Losque que l'on veux manipuler un champs intégré à `kustomize`, (si le binaire kustomize, est installé => kustomize edit set <TAB>) :
   - annotation
   - buildmetadata
   - configmap
   - image
   - label
   - nameprefix
   - namespace
   - namesuffix
   - replicas
   - secret         
````
kustomize/
└── mon-projet1/
   ├── base/
   │   ├── deployment.yaml
   │   ├── service.yaml
   │   └── kustomization.yaml
   └── overlays/
       ├── dev/
       │   └── kustomization.yaml <---------
       └── prod/                           |----- Utiliser directement ces fichier
           └── kustomization.yaml <---------
````

`- 2.1` Créer le dossier ici => prod.
````
mkdir -p kustomize/overlays/prod
````

`- 2.2` Créer le fichier kustomization.yaml
````
vim kustomize/overlays/prod/kustomization.yaml
````
````
# ../../base => Récupére la configuration de /base (dit à l'api server, ma configuration de référence est celle dans "base") 
resources:
  - ../../base
patches:
# utilisation du fichier patch-replicas.yaml pour modifier le nombre de réplicas de base.( Ligne pour modifier le deploiement des fichier .yaml présent dans base)
  - path: patch-replicas.yaml
    target:
      kind: Deployment
      name: web
````

`- 2.3` créer le fichier `patch-replicas.yaml`
````
vim kustomize/overlays/prod/patch-replicas.yaml
````
````
- op: replace
  path: /spec/replicas
  value: 5
````

### `-3-` Vérrif du fichier
````
kubectl kustomize kustomize/overlays/prod/
````

### `-4-` Déploiement
````
kubectl apply -k overlays/prod/
````

### **=== Arborécence type ===**
````
kustomize/
├── base/
│   ├── deployment.yaml      # replicas: 1, image par défaut
│   ├── service.yaml
│   └── kustomization.yaml
│
└── overlays/
    ├── dev/
    │   ├── kustomization.yaml
    │   └── patch.yaml        # replicas: 1, image tag "dev"
    │
    ├── staging/
    │   ├── kustomization.yaml
    │   └── patch.yaml        # replicas: 2
    │
    └── prod/
        ├── kustomization.yaml
        └── patch.yaml        # replicas: 5, limits CPU/mem plus hauts
````
