## Taints & Tolerations

---

[https://kubernetes.io/docs/concepts/scheduling-eviction/taint-and-toleration/](https://kubernetes.io/docs/concepts/scheduling-eviction/taint-and-toleration/)

---

- `Taints` & `Tolerations` agissent ensemble pour permettre au `scheduler` de placer des **pods** (**Tolerations**), sur les **nodes** (**tains**) sui peuvent les accépter.

- Ensemble `clé=valeur`

- On utilise surtout ce mécanisme afin de `repousser` des `pods` de certains `nodes`.

- Il exite 3 Types de `Taints` :
   - **NoSchedule** : `Règle Strict` Ne pas ajouter de nouveaux pods
   - **PreferNoSchedule** : `Règle Souple`évite au maximum de placer le Pod sur ce Node.  
   - **NoExecute** : `Déplacement Forcé` Déplace tous les pods du node

- Des taints `Automatique` peuvent être émis par le `control-plane` (Avec application `NoSchedule / NoExecute`)
   - **not-ready** : le `node` ne répond plus aux `ping` **NoSchedule / NoExecute**
   - **unreachable** : le `node` à perdu le contact avec le `control-plane` **NoSchedule / NoExecute**
   - **memory-pressure** : `RAM` saturée **NoSchedule**
   - **disk-pressure** : `Espace Disque` ou `Inodes` saturés **NoSchedule**
   - **pid-pressure** : Trop de `Processus` **NoSchedule**
   - **network-unavailable** : `Connection` réseau défaillante **NoSchedule**
   - **unschedulable** : node marqué `hors service` => `kubectl cordon / drain` **NoSchedule** 
   - **FORMAT** => node.kubernetes.io/`<taints ci dessus>` 
 - Si un pod à le bon `Tolerations` il n'est pas affecté par le Taints.

- Comparateur `Toleration`
   - Equal présence **Obligatoire** `key=value`
   - Exists présence **Uniquement**  `key`   


**=== Exemple Taints / Toleration Corespondances ===**
````
# 1. Dans le manifest du NODE => (spec.taints)
spec:
  taints:
  - key: "env"
    value: "prod"
    effect: "NoSchedule"

# --------------------------------------------------

# 2. Dans le manifest du POD => (spec.tolerations)
apiVersion: v1
kind: Pod
metadata:
  name: my-app
spec:
  containers:
  - name: app
    image: nginx
  tolerations:
  - key: "env"         # Doit matcher la key du Node
    operator: "Equal"  # Equal (défaut) ou Exists
    value: "prod"      # Doit matcher la value du Node
    effect: "NoSchedule" # Doit matcher l'effect du Node
````

### `-4-` Création d'un pod avec `tolerations`
````
kubectl run toleration-pod --image=nginx --dry-run=client -o yaml > toleration-nginx.yaml
````
````
vim toleration-nginx.yaml
````
````
apiVersion: v1
kind: Pod
metadata:
  labels:
    run: toleration-nginx
  name: toleration-nginx
spec:
  containers:
  - image: nginx
    name: toleration-nginx
    resources: {}
##########################
  tolerations:           #
  - key: "storage"       #
    operator: "Equal"    #  <===== Ajouter ce bloc
    value: "ssd"         #
    effect: "NoSchedule" #
##########################
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
````


### `-6-` Création d'un pod sans `toleration`
````
kubectl run toleration-pod-2 --image=nginx
````
