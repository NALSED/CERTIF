## Taints & Tolerations

---

- `Taints` & `Tolerations` agissent ensemble pour permettre au `scheduler` de placer des **pods** (**Tolerations**), sur les **nodes** (**tains**) sui peuvent les accépter.

- Ensemble `clé=valeur`

- On utilise surtout ce mécanisme afin de `repousser` des `pods` de certains `nodes`.

- Il exite 3 Types de `Taints` :
   - **NoSchedule** : `Règle Strict` Ne pas ajouter de nouveaux pods
   - **PreferNoSchedule** : `Règle Souple`évite au maximum de placer le Pod sur ce Node.  
   - **NoExecute** : `Déplacement Forcé` Déplace tous les pods du node

- Des taints `Automatique` peuvent être émis par le `control-plane` (Avec application `NoSchedule / NoExecute`)
   - not-ready
   - unreachable
   - memory-pressure
   - disk-pressure
   - pid-pressure
   - network-unavailable
   - unschedulable 
    
 - Si un pod à le bon `Tolerations` il n'est pas affecté par le Taints.

- Comparateur `Toleration`
   - Equal présence **Obligatoire** `key=value`
   - Exists présence **Uniquement**  `key`   


**=== Exemple ===**
````
# 1. Dans le manifest du NODE => (spec.taints)
spec:
  taints:
  - key: "env"
    value: "prod"
    effect: "NoSchedule"

# --------------------------------------------------

# 2. Dans le manifest du POD => (spec.tolerations)
apiVersion: v1
kind: Pod
metadata:
  name: my-app
spec:
  containers:
  - name: app
    image: nginx
  tolerations:
  - key: "env"         # Doit matcher la key du Node
    operator: "Equal"  # Equal (défaut) ou Exists
    value: "prod"      # Doit matcher la value du Node
    effect: "NoSchedule" # Doit matcher l'effect du Node
````
