## Options configurations Nodes

[https://kubernetes.io/docs/concepts/scheduling-eviction/assign-pod-node/](https://kubernetes.io/docs/concepts/scheduling-eviction/assign-pod-node/)

---

- Il est possible dedéployer un pod sur un nodes souhaité via les `labels`.

- Visible via :
````
kubectl get pods --show-label
````

- Les label sont utilisés par , `Services`, `Deployments`, `NetworkPolicies`. Il servent à identifier un pod, mais aussi )à mapper plusieurs pods, en incluant ou excluant via les label, pour leur appliquer une politique.

**=== Exemple ===**
````
kubectl get nodes --show-labels
````
````
NAME           STATUS   ROLES           AGE   VERSION   LABELS
k8s-worker1    Ready    <none>          16d   v1.37.0   beta.kubernetes.io/arch=amd64,beta.kubernetes.io/os=linux,kubernetes.io/arch=amd64,kubernetes.io/hostname=k8s-worker1,kubernetes.io/os=linux
````

- Ici le `worker1` à plusieurs `label`, création d'un nouveau
````
kubectl label nodes k8s-worker1 disktype=ssd
````
````    
                                                                                                                         ICI
k8s-worker1    Ready    <none>          16d   v1.37.0   beta.kubernetes.io/arch=amd64,beta.kubernetes.io/os=linux,###disktype=ssd###,kubernetes.io/arch=amd64,kubernetes.io/hostname=k8s-worker1,kubernetes.io/os=linux
````

- Créer le fichier yaml du pods souhaité
````
kubectl create deploy nginx-label --image=nginx --dry-run=client -o yaml > nginx.yaml
````

-Editer
````
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: nginx-label
  name: nginx-label
spec:
  replicas: 1
  selector:
    matchLabels:
      app: nginx-label
  template:
    metadata:
      labels:
        app: nginx-label
    spec:
      nodeSelector:
        disktype: ssd
      containers:
      - image: nginx
        name: nginx
````
