## Utilisation de la commande `kubeadm init`

---

- kubeadm init` => [OPTION] (https://kubernetes.io/docs/reference/setup-tools/kubeadm/kubeadm-init/#options)

- Commande effectuée uniquement sur le `control plane`, elle met en place le cluster comme décrit ci dessous:

`-1-` Vérification de l'état du système, avant d'y effectuer des modification, des avertissement peuvent ressortir, et peuvent être ignorés via la commande `--ignore-preflight-errors=<list-des-erreurs>`

`-2-` Génère une autorité de certification (CA) auto signée (ou utilise une existante si spécifiée via la commande `--cert-dir`), le path par défaut des certificats est `/etc/kubernetes/pki`.

`-3-` Écriture des fichiers `Kubeconfig` dans `/etc/kubernetes/`, pour kubelet, le controller-manager et le scheduler, qui seront utlisés pour les connexions à l'API server, chacun avec sa propre identité, ainsi qu'un fichier kubeconfig supplémentaire pour l'administration, nommé `admin.conf`.

`-4-` Génère des manifestes statiques de Pod pour l'API server, le controller manager et le scheduler, dans `/etc/kubernetes/manifestes`.

`-5-` Applique les étiquettes (labels) et marques (taints) au noeud control-plane 

`-6-` Génération de token afin que les node supplémentaire puisse entrer dans le cluster

`-7-` Génère le jeton que les noeuds additionnels peuvent utiliser pour s'enregistrer avec un control-plane. Et configuration et création, `ConfigMap`, `RBAC`, `API CSR`

`-8-` Intallation de `DNS Core`

Pour plus d'information sur le déroulé exact de la commande `kubeadm init` => [DOC_OFFICIELLE](https://kubernetes.io/fr/docs/reference/setup-tools/kubeadm/kubeadm-init/#init-workflow)
