## Configuration `HA`

---

`[NOTE]`

⚠️ Contrairement à mon cluster, et aux bonnes pratiques, on ne met jamais le `Load Balancer` ET `kube-apiserver` sur la même VM, confit de ports, debugage plus complexe, sécurité. ⚠️

- Point important le cluster `HA` à été créer avec un cluster déja existant, donc les commandes ne sont pas tout à fait les mêmes.

-  Le [blueprint](https://github.com/NALSED/CERTIF/blob/main/CKA/PRACTICE/BLUEPRINT_OFFICIELLE.md), demande de savoir administrer avec `kubeadm`.

---

[DOC_KUBERNETES](https://kubernetes.io/docs/setup/production-environment/tools/kubeadm/high-availability/#first-steps-for-both-methods)

### -1- Tester la connection au `LoadBalancer`
````
nc -zv -w 2 192.168.0.15 6443

# Sortie
Connection to 192.168.0.15 6443 port [tcp/*] succeeded!
````

### -2- Initialiser le cluster `control plane`
````
sudo kubeadm init --control-plane-endpoint "192.168.0.15:6443" --upload-certs
# !!! Sauver l'output de la commande !!!
````
# Sortie 
````
Your Kubernetes control-plane has initialized successfully!

To start using your cluster, you need to run the following as a regular user:

################
## PARTIE =1= ##
#######################################################################
  mkdir -p $HOME/.kube
  sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
  sudo chown $(id -u):$(id -g) $HOME/.kube/config
#######################################################################

Alternatively, if you are the root user, you can run:

  export KUBECONFIG=/etc/kubernetes/admin.conf

You should now deploy a pod network to the cluster.

################
## PARTIE =2= ##
#######################################################################
Run "kubectl apply -f [podnetwork].yaml" with one of the options listed at:
#######################################################################

 https://kubernetes.io/docs/concepts/cluster-administration/addons/

You can now join any number of the control-plane node running the following command on each as root:


################
## PARTIE =3= ##
#######################################################################
  kubeadm join 192.168.0.15:6443 --token <TOKEN> \
        --discovery-token-ca-cert-hash sha256:<HASH> \
        --control-plane --certificate-key <CERT_KEY>
#######################################################################

Please note that the certificate-key gives access to cluster sensitive data, keep it secret!
As a safeguard, uploaded-certs will be deleted in two hours; If necessary, you can use
"kubeadm init phase upload-certs --upload-certs" to reload certs afterwards.

Then you can join any number of worker nodes by running the following on each as root:


################
## PARTIE =4= ##
#######################################################################
  kubeadm join 192.168.0.15:6443 --token <TOKEN> \
        --discovery-token-ca-cert-hash sha256:<HASH>
#######################################################################
````
