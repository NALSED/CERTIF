## Sauvegarde de `etcd`

---
- `etcd` est la `db` de kubernetes, elle contient toutes les ressources du cluster, son importance est donc `critique`.

- L'utilitaire `etcdctl` n'est pas inclus dans le package standard de kubetools.
````
sudo apt install etcd-client
````

### ⚠️ Pour utiliser `etcdctl`, il faut spécifier : ⚠️
- `endpoint`
- `cacert`
- `cert`
- `key`

- Utiliser `ps` pour trouver ces valeurs :
````
ps aux | grep etcd
````

---

**=== Récapitulation Étapes : ===**

`-1-` Installer `etcdctl`

`-2-` Récupérer les informations nécessaires au BackUp

`-3-` Faire le BackUp

`-4-` Vérification

---

`[NOTE]`

- Afin d'être sûr d'utiliser la `bonne version` de `l'API`, la `V3`

- Bon réflexe pour qu'il n'y ait pas d'ambiguïté

````
ETCDCTL_API=3 <COMMANDE>
````



###  `-2-` Récupérer les informations nécessaires au BackUp

`- 2.1` Ici utilisation de `ps aux` et `/etc/kubernetes/pki/etcd`
````
ps aux | grep etcd

cd /etc/kubernetes/pki/etcd
````

---

### `-3-` Faire le BackUp

`- 3.1` Après récupération des informations
````
etcdctl --endpoints=https://127.0.0.1:2379 \
--cacert=/etc/kubernetes/pki/etcd/ca.crt \
--cert=/etc/kubernetes/pki/etcd/server.crt \
--key=/etc/kubernetes/pki/etcd/server.key \
snapshot save /tmp/EtcdBackUp.db
````

`- 3.2` `Option intéressante` pour ne pas être submergé par les valeurs des clés `etcd` :
````
# -1- Exclure les valeurs, n'afficher que les clés
sudo etcdctl --endpoints=https://127.0.0.1:2379 \
--cacert=/etc/kubernetes/pki/etcd/ca.crt \
--cert=/etc/kubernetes/pki/etcd/server.crt \
--key=/etc/kubernetes/pki/etcd/server.key \
get / --prefix --keys-only

# -2- BackUp
sudo etcdctl --endpoints=https://127.0.0.1:2379 \
--cacert=/etc/kubernetes/pki/etcd/ca.crt \
--cert=/etc/kubernetes/pki/etcd/server.crt \
--key=/etc/kubernetes/pki/etcd/server.key \
snapshot save /tmp/EtcdBackUp.db
````

- `Sortie attendue`
````
Snapshot saved at /tmp/EtcdBackUp.db
````

---

### `-4-` Vérification

- Après un backup de `etcd` il est bon de vérifier la sauvegarde.
````
sudo etcdctl --write-out=table snapshot status /tmp/EtcdBackUp.db

# Sortie
┌──────────┬──────────┬────────────┬────────────┐
│   HASH   │ REVISION │ TOTAL KEYS │ TOTAL SIZE │
├──────────┼──────────┼────────────┼────────────┤
│ 4a8f3931 │    66619 │       1133 │     3.9 MB │
└──────────┴──────────┴────────────┴────────────┘
````

`[NOTE]`

- La méthode de vérification avec `etcdctl` est dépréciée, utiliser `etcdutl`
````
sudo apt install etcd-server

etcdutl snapshot status /tmp/EtcdBackUp.db

# Sortie
sudo etcdutl snapshot status EtcdBackUp.db
4a8f3931, 66619, 1133, 3.9 MB
````
