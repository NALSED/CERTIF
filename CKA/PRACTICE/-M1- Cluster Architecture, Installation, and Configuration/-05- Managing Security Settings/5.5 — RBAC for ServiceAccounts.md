 ## RBAC => ServiceAccounts

 ---

 - Pour éditer les droits pour un `Service Account` (Compte qui permet à un service de se connecter au cluster) :
 
    -  Création d'un `Roles` (Droits)
    -  Création d'un `RoleBinding` pour faire le liens entre le `Roles et le `Service`.

- Tous les `Pods` on un `ServiceAccount` avec un accés minimal, mais pour des besoins spécifiques un `ServiceAccount` dédié doit être créé.

---

### `=== EXEMPLE ===`

- Dans cet exemple :

**-1- Création d'un pod**

**-2- Test via curl sur l'API de Kubertenes**

**-3-Création d'un Role et BindingRoles**

**-4- Second test avec curl**


----


### **-1- Création d'un pod + Prérequis +Test**
````
run test-roles --image=alpine -- sleep 3000
````

- Shell du container
````
kubectl exec -it test-roles -- sh
````

- Installation de curl 
````
apk add --update curl
````

- `ServiceAccount` par défaut
````
kubectl get pods test-roles -o yaml | grep serviceAccount
````
````
  serviceAccount: default
  serviceAccountName: default
      - serviceAccountToken:
````

### **-2- Test via curl sur l'API de Kubertenes**

- Test d'accés à l'API de Kubernetes => Anonyme 
````
curl https://kubernetes/api/v1 --insecure
````

- Accés refusé
````
  "kind": "Status",
  "apiVersion": "v1",
  "metadata": {},
  "status": "Failure",
  "message": "forbidden: User \"system:anonymous\" cannot get path \"/api/v1\"",
  "reason": "Forbidden",
  "details": {},
  "code": 403
````

- Test d'accés à l'API de Kubernetes => Avec TOKEN
````
# Entrer le TOKEN dans un variable
TOKEN=$(cat run/secrets/kubernetes.io/serviceaccount/token)

# Test avec le TOKEN
curl -H "Authorization: Bearer $TOKEN" https://kubernetes/api/v1 --insecure
````

- Test approuvé
````

  "kind": "APIResourceList",
  "groupVersion": "v1",
  "resources"
[...]
````

- Test Status Pods
````
curl -H "Authorization: Bearer $TOKEN" https://kubernetes/api/v1/namespaces/default/pods --insecure
````

- Accés refusé car on ne peux lister la resource POD.
````
 "kind": "Status",
  "apiVersion": "v1",
  "metadata": {},
  "status": "Failure",
  "message": "pods is forbidden: User \"system:serviceaccount:default:default\" cannot list resource \"pods\" in API group \"\" in the namespace \"default\"",
  "reason": "Forbidden",
  "details": {
    "kind": "pods"
  },
  "code": 403
````

### **-3-Création d'un ServiceAccount + Role et BindingRoles**

- Création ServiceAccount
````
kubectl create sa martin
````

- Création Role
````
kubectl create role pods-test-role --resource=pods --verb=list
````

- création RoleBinding
````
kubectl create rolebinding pods-test-rolebinding --role=pods-test-role --serviceacco
unt=default:martin
````

- POUR CET EXEMPLE création d'un pode avec le ServiceAccount martin
````
vim podsrole.yaml
````
````
apiVersion: v1
kind: Pod
metadata:
  name: podsrole
spec:
  serviceAccountName: martin
  containers:
  - name: alpine
    image: alpine:3.9
    command:
    - "sleep"
    - "3600"
````
````
kubectl apply -f podsrole.yaml 
````
