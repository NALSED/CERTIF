 ## RBAC => ServiceAccounts

 ---

 - Pour éditer les droits pour un `Service Account` (Compte qui permet à un service de se connecter au cluster) :
 
    -  Création d'un `Roles` (Droits)
    -  Création d'un `RoleBinding` pour faire le liens entre le `Roles et le `Service`.

- Tous les `Pods` on un `ServiceAccount` avec un accés minimal, mais pour des besoins spécifiques un `ServiceAccount` dédié doit être créé.

### **-1- Création d'un pod + Prérequis +Test**
````
run test-roles --image=alpine -- sleep 3000
````

- Shell du container
````
kubectl exec -it test-roles -- sh
````

- Installation de curl 
````
apk add --update curl
````

- `ServiceAccount` par défaut
````
kubectl get pods test-roles -o yaml | grep serviceAccount
````
````
  serviceAccount: default
  serviceAccountName: default
      - serviceAccountToken:
````

### **-2- Test via curl sur l'API de Kubertenes**

- Test d'accés à l'API de Kubernetes => Anonyme 
````
curl https://kubernetes/api/v1 --insecure
````

- Accés refusé
````
  "kind": "Status",
  "apiVersion": "v1",
  "metadata": {},
  "status": "Failure",
  "message": "forbidden: User \"system:anonymous\" cannot get path \"/api/v1\"",
  "reason": "Forbidden",
  "details": {},
  "code": 403
````

- Test d'accés à l'API de Kubernetes => Avec TOKEN
````
# Entrer le TOKEN dans un variable
TOKEN=$(cat run/secrets/kubernetes.io/serviceaccount/token)

# Test avec le TOKEN
curl -H "Authorization: Bearer $TOKEN" https://kubernetes/api/v1 --insecure
````

- Test approuvé
````

  "kind": "APIResourceList",
  "groupVersion": "v1",
  "resources"
[...]
````
