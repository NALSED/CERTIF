# Introduction User / API Access, ServiceAccount

---

### -1- Kubernetes ne gère pas les utilisateurs lui-même.

- Contrairement à un système classique avec une table d'utilisateurs. Il n'y a pas d'objet User dans l'API.

### -2- User venant de l'extérieur

- Certificats X.509

- OpenID Connect externe (Google, Active Directory, Okta, etc.)

### -3- Les Pods, eux, ont un vrai objet Kubernetes : `ServiceAccount`

- Contrairement aux humains, les Pods ont besoin d'une identité gérée nativement par K8s pour appeler l'API

- Si aucune précision sur `ServiceAccount` il sera attribué `default` => avec des droits minimaux.
