## Présentation Security Context

---

[DOC](https://kubernetes.io/docs/tasks/configure-pod-container/security-context/)

- La configuration de `Security Context` passe par des fichier .yaml

- C'est une partie du fichier `.yaml`, avec pour entête `securityContext:`, les différente option sont disponible dans la doc ci-dessus.

- `Security Context` créé un héritage en `champs par champs` c'est à dire que si une régle est déffini dans la partie `pod` et `container`, la partie container prend le dessu sur la configuation du pod.

---

- Voici un exemple d'un fichier `.yaml` avec `Security Context` ( Exemple tiré de [Sander Van Guth](https://github.com/sandervanvugt/cka/blob/master/security-context.yaml)) 

````
apiVersion: v1
kind: Pod
metadata:
  name: security-context-demo
spec:
  securityContext: 
    runAsUser: 1000
    runAsGroup: 1000
    fsGroup: 2000
  volumes:
  - name: securevol
    emptyDir: {}
  containers:
  - name: sec-demo
    image: busybox
    command: ["sh", "-c", "sleep 3600"]
    volumeMounts:
    - name: securevol
      mountPath: /data/demo
    securityContext:
      allowPrivilegeEscalation: false
````

- Prendre le shell du container
````
kubectl exec -it security-context-demo -- sh
````

- On vois ci dessous que la politique `ID` est appliqué
````
~ $ ps
PID   USER     TIME  COMMAND
    1 1000      0:00 sleep 3600
    7 1000      0:00 sh
   13 1000      0:00 ps

~ $ cd data/
/data $ ls -l
total 4
drwxrwsrwx    2 root     2000          4096 Sep 23 11:35 demo

/data $ id
uid=1000 gid=1000 groups=1000,2000
````
