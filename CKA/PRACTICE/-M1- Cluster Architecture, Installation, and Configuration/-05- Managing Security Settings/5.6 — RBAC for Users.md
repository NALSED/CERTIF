## RBAC et User

---

- Dans kubernetes l'accées des`user` sont gérer par des solution extérieur (LDAP, AD, etc...) alors que les droits sont gérer par `RBAC`

-  Pour créer un Compte Utilisateurs sur Kubernetes :

   - 1 Créer un paire de clés pub/priv
   - 2 Créer un certificat pour signer les requêtes
   - 3 Signer le certificat
   - 4 Créer le fichier de configuration avec les objets créer ci dessus
   - 5 Créer RBAC Role
   - 6 Créer RBAC Rolebinding

### `-1-` Création de `Namespace`
````
kubectl create ns user-tintin
````

---

### `-2-` Création `user` 
````
useradd -m -G sudo -s /bin/bash tintin
````
````
passwd tintin
````

---

### `-3-` création `clé priv` `.csr` `clé pub`

` -3.1`
````
su - tintin
````

` -3.2` Générer un clé privée 
````
openssl genrsa -out tintin.key 2048
````

` -3.3` CSR
````
openssl req -new -key tintin.key -out tintin.csr -subj "/CN=tintin/O=k8s"
````

` -3.4` Signer le CSR avec le CA de Kubernetes
````
sudo openssl x509 -req -in tintin.csr -CA /etc/kubernetes/pki/ca.crt
````

` -3.5` Créer le certificat de tintin avec le pki de kubernetes
````
sudo openssl x509 -req -in tintin.csr \
-CA /etc/kubernetes/pki/ca.crt \
-CAkey /etc/kubernetes/pki/ca.key \
-CAcreateserial -out tintin.crt \
-days 1800
````

---

### `-4-` Création des `fichiers d'identifiants kubernetes`

`- 4.1` créer le fichier `.kube`
````
mkdir /home/tintin/.kube
````

`- 4.2` copier la configuration utilisateur `admin.conf` (comme un template)
````
sudo cp -i /etc/kubernetes/admin.conf /home/tintin/.kube/config
````

`- 4.3` Appliquer la propriété de manière `récursive` sur `.kube`
````
sudo chown -R tintin:tintin /home/tintin/.kube
````

`- 4.4` Entrer les identifiants de l'utilisateur en tant qu'`objet Kubernetes`.
````
kubectl config set-credentials tintin \
--client-certificate=/home/tintin/tintin.crt \
--client-key=/home/tintin/tintin.key 
````


---

### `-5-` création d'un context utilisateur

`[NOTE]`

- Le `context` est défini dans le fichier .kube/config de l'utilisateur concerné.

- Il contient 3 éléments :

   -  `cluster` — quel cluster contacter (l'adresse de l'API server)
   -  `user` — quelle identité utiliser pour s'authentifier
   -  `namespace` (optionnel) — dans quel namespace travailler par défaut



`- 5.1` Créer le context
````
kubectl config set-context tintin-context \
--cluster=kubernetes \
--namespace=user-tintin \
--user=tintin
````

`- 5.2` application du context
````
kubectl config use-context tintin-context 
````

---

### `-6-` `Role` / `RoleBinding`

`- 6.1` Role
````
kubectl create role tintin-role -n user-tintin \
--verb=get,list,watch,create,update,patch,delete \
--resource=deployment,replicasets,pods
````

`- 6.2` RoleBinding
````
kubectl create rolebinding tintin-role-binding -n user-tintin  \
--user=tintin \
--role=tintin-role
````
