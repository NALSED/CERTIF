## Gestion de base d'un node

---

### === CORDON ===

- Pour pouvoir `investiguer` sur un node il est utile de mettre en `quarantaine` le `node`

- Pour ce faire utiliser
````
kubectl cordon <NODE_NAME>

# Sortie
node/k8s-worker1 cordoned
````

- Après la mise en quarantaine, le `node` devient `SchedulingDisabled`, plus aucun pod ne pourra être créé par le `Scheduler` sur `k8s-worker1`.

- On peut aussi constater qu'un nouveau champ est apparu dans la sortie description de `k8s-worker1` => `Taints` 
````
kubectl describe node k8s-worker1 | less
````
````
Taints:             node.kubernetes.io/unschedulable:NoSchedule
````

- Lorsque l'investigation est finie
````
kubectl uncordon <NODE_NAME>

# Sortie
node/k8s-worker1 uncordoned
````

---

### === DRAIN ===

- Même effet de mise en quarantaine que `cordon`, et en plus suppression de tous les pods en cours
