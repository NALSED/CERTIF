## `Static Pods`

---

- Les `Statics Pods` sont défini ici : `/etc/kubernetes/manifests`

- Ils sont une `partie essentiel` du fonctionement de `Kubernetes` :
  
     - etcd.yaml
     
     - kube-apiserver.yaml
     
     - kube-controller-manager.yaml
     
     - kube-scheduler.yaml
 
- On peux ajouter des `Static Pods` en ajoutant un fichier .yaml dans de dossier, et kubelet se chargera de récupérer la nouvelle configuration et de l'appliquer.

- Pour changer le chemin par defaut de configuration des `Static Pods` editer le fichier `/var/lib/kubelet/config.yaml` et `sudo systemctl restart kubelet`

- Ils fonctionne même si `l'API server` ne fonctionne plus, car kubelet dépend de `systemd`

---

`=== Création Static Pods ===`

-1- créer le fichier .yaml sur `Master` via la commande suivante la commande est lancé en `--dry-run`, car on ne veux pas le container sur master mais sur worker. 
- Le `-o` est pour avoir un output formaté en `.yaml` vers => $HOME/static.yaml
````
kubectl run staticpods --image=nginx --dry-run=client -o yaml > $HOME/static.yaml
````

-2-
Créer et éditer le fichier sur le `worker1` dans le dossier `/etc/kubernetes/manifests`
````
sudo vim /etc/kubernetes/manifests/nginx.yaml
````

````
apiVersion: v1
kind: Pod
metadata:
  labels:
    run: staticpods
  name: staticpods
spec:
  containers:
  - image: nginx
    name: staticpods
    resources: {}
  dnsPolicy: ClusterFirst
  restartPolicy: Always
status: {}
````
